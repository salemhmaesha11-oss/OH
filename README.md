# OH — إدارة مستلزمات طب الأسنان

موقع عربي متجاوب لمركز OH لإدارة طلبات الطلاب ومخزون مستلزمات طب الأسنان ومبيعات البائع. الصفحة الرئيسية تفتح مباشرة على نموذج الطلب؛ دخول المالك والبائع متاح من زر «دخول الإدارة» في أعلى الصفحة. يظهر بنر OH المشترك في رأس الموقع من [`oh-header-banner.jpg`](./oh-header-banner.jpg)، ويظل شعار الدخول موجوداً في [`oh-logo.svg`](./oh-logo.svg)، وصورة معاينة مشاركة الرابط في [`oh-social-card.png`](./oh-social-card.png). عناوين Open Graph في `index.html` تستخدم النطاق `ohshop.netlify.app`؛ حدّثها إذا تغيّر نطاق النشر. تُنشر الواجهة ودالة الحسابات على Netlify، وتُستخدم Supabase Auth وPostgres للتحقق من حسابات الموظفين وصلاحياتهم.

تعرض الأسعار بالليرة السورية (ل.س). أسعار المواد في بيانات التجربة أمثلة فقط؛ حدّثها من واجهة المالك قبل استخدامها.

يدعم الموقع التثبيت كتطبيق ويب تقدمي على Android وiOS عند نشره عبر HTTPS. تُحفظ واجهة الموقع وموارده العامة مؤقتاً، كما تُحفظ سلة الطالب على الجهاز. إذا انقطع الاتصال أثناء إرسال طلب طالب، يُخزّن الطلب في IndexedDB ويُعاد إرساله تلقائياً عند عودة الشبكة؛ قد يتطلب iOS فتح التطبيق مجدداً لأن Background Sync غير متاح في جميع المتصفحات. عمليات الإدارة لا تُصفّ دون اتصال لأنها تتطلب جلسة موظف صالحة. لتفعيل إعادة الإرسال الآمن، طبّق ترحيل [`supabase/migrations/20261020000000_offline_guest_orders.sql`](./supabase/migrations/20261020000000_offline_guest_orders.sql) بعد ترحيلات قاعدة البيانات.

## التشغيل المحلي

ثبّت الاعتماديات مرة واحدة ثم شغّل خادم الملفات الثابتة مع fallback لمسارات تطبيق الصفحة الواحدة:

```sh
npm install
npm run dev
```

يفتح `serve -s` الموقع محلياً ويعيد المسارات غير المعروفة إلى `index.html`. لكنه يقدم ملفات ثابتة فقط ولا يشغّل دوال Netlify؛ لذلك تسجيل دخول الموظفين يتطلب تشغيل `netlify dev` بدلاً منه بعد تثبيت Netlify CLI وضبط متغيرات البيئة المطلوبة. مسار الدالة المستخدم في الموقع هو `/.netlify/functions/auth`.

```sh
npm install -g netlify-cli
npm run dev:netlify
```

عند التشغيل المحلي، عيّن متغيرات البيئة في نافذة PowerShell نفسها قبل بدء Netlify Dev:

```powershell
$env:SUPABASE_URL = "رابط مشروع Supabase"
$env:SUPABASE_PUBLISHABLE_KEY = "مفتاح النشر العام"
$env:SUPABASE_SECRET_KEY = "المفتاح السري"
npm run dev:netlify
```

لا تضع المفتاح السري في `index.html` أو تشاركه. أعد تشغيل Netlify Dev بعد تعيين المتغيرات.

### حسابات تجريبية محلية

لإنشاء حسابَي مالك وبائع للتطوير فقط، وبعد تطبيق مخطط Supabase والترحيلات، عيّن `SUPABASE_URL` و`SUPABASE_SECRET_KEY` محلياً إلى مشروعك ثم نفّذ:

```sh
npm run seed:demo-staff
```

ينشئ السكربت أو يعيد ضبط الحسابات التجريبية التالية:

| الدور | اسم المستخدم | كلمة المرور المؤقتة |
|---|---|---|
| المالك | `owner_demo` | `12345678` |
| البائع | `seller_demo` | `12345678` |

هذه بيانات دخول ضعيفة ومشتركة للاختبار المحلي فقط. غيّر كلمتي المرور فوراً، ولا تشغّل السكربت على مشروع أو موقع إنتاجي. يحتفظ السكربت بالمفتاح السري في متغير البيئة ولا يكتبه في الملفات.

## الحسابات وتسجيل الدخول

- يحتاج **المالك والبائع** إلى حساب وكلمة مرور لتسجيل الدخول. لا توجد قائمة لاختيار الدور؛ صلاحية المستخدم تُقرأ من ملفه في Supabase.
- يستطيع المالك إنشاء حساب بائع، وتعديل اسمه واسم المستخدم وإعادة تعيين كلمة مروره من صفحة الحسابات.
- يمكن للبائع تعديل بيع أو تسجيل مرتجع خلال 24 ساعة من إنشائه. يسجل النظام كل تعديل، ويعيد أو يخصم المخزون وفق فرق الكميات.
- يستطيع البائع فتح تفاصيل طلب الطالب للاطلاع على الاسم ورقم الموبايل والمواد والأسعار؛ وتبقى الطلبات الجاهزة ظاهرة في سجل الطلبات بعد التجهيز. يعرض سجل المالك اسم البائع الكامل واسم المستخدم المرتبط بحسابه.
- يستطيع المالك تعبئة المخزون مع تسجيل تكلفة شراء الوحدة لكل دفعة، وتعديل أسعار المواد. يمكنه أرشفة سجل بيع واستعادته؛ الأرشفة تخفيه من القوائم النشطة ولا تحذفه أو تغيّر المخزون.
- خيار **تذكرني على هذا الجهاز** يحفظ جلسة الموظف على الجهاز؛ عند إلغاء اختياره تبقى الجلسة حتى إغلاق التبويب.
- لا يوجد تسجيل ذاتي للموظفين. يمكن للطالب متابعة طلب المواد كضيف كما كان في النموذج الأولي.

## سجل الموظفين وكلمات المرور

يحتوي `public.employees` على معرّف الحساب (`id` من نوع UUID)، واسم المستخدم، والاسم الكامل، والدور، وتاريخ إنشاء الحساب. كلمة المرور لا تُحفظ في هذا العرض ولا في `profiles`: تخزّنها Supabase Auth بصيغة تحقق آمنة، ولا يمكن استرجاعها كنص مقروء. إعادة التعيين من واجهة المالك تمر عبر دالة Netlify ومفتاح Supabase السري على الخادم.

إذا كان جدولك الحالي يحتوي عمود `password` قديماً، فلن يستخدمه تسجيل الدخول. أنشئ/أعد تعيين كلمة مرور الحساب من Supabase Auth، وبعد ترحيل الحسابات احذف العمود القديم حتى لا تبقى كلمات مرور مكشوفة في قاعدة البيانات.

## إعداد Supabase وNetlify

1. لمشروع Supabase جديد فقط، شغّل [`supabase/schema.sql`](./supabase/schema.sql) مرة واحدة، ثم الترحيلات [`supabase/migrations/20261010000000_sales_management.sql`](./supabase/migrations/20261010000000_sales_management.sql)، و[`supabase/migrations/20261010010000_product_images.sql`](./supabase/migrations/20261010010000_product_images.sql)، و[`supabase/migrations/20261010020000_seller_product_images.sql`](./supabase/migrations/20261010020000_seller_product_images.sql)، و[`supabase/migrations/20261010030000_seller_returns_48_hours.sql`](./supabase/migrations/20261010030000_seller_returns_48_hours.sql)، ثم [`supabase/migrations/20261015000000_student_order_phone.sql`](./supabase/migrations/20261015000000_student_order_phone.sql)، و[`supabase/migrations/20261015010000_profit_accounting.sql`](./supabase/migrations/20261015010000_profit_accounting.sql)، وأخيراً [`supabase/migrations/20261015020000_material_requests.sql`](./supabase/migrations/20261015020000_material_requests.sql) بهذا الترتيب. للمشروع القائم، **لا تعِد تشغيل `schema.sql`**؛ شغّل فقط الترحيلات التي لم تُطبّق بعد. يستطيع البائع تعديل البيع أو تسجيل مرتجع خلال 48 ساعة من البيع. تضيف ترحيلات الصور عمود `image_url` وتسمح للبائع بتغيير صورة المنتج فقط عبر دالة تتحقق من صلاحية الموظف ونوع الصورة وحجمها، دون منحه صلاحية تعديل بقية بيانات المادة. يضيف ترحيل إدارة المبيعات المرتجعات وتدقيق التعديلات وتقييد سجل البائع والأرشفة والتعبئة الموثقة، ويضيف ترحيل الطالب رقم الموبايل، ويضيف ترحيل المحاسبة نسب الربح وتكاليف الدفعات والمصروفات وتقارير صافي الربح، أما ترحيل طلبات المواد فيتيح للبائع إرسال طلبات التزويد وترشيحات الطلب المتوقّع للمالك لمراجعتها.
   بعد ذلك شغّل [`supabase/migrations/20261017000000_workflow_improvements.sql`](./supabase/migrations/20261017000000_workflow_improvements.sql) ثم [`supabase/migrations/20261020000000_offline_guest_orders.sql`](./supabase/migrations/20261020000000_offline_guest_orders.sql) على المشروع الجديد أو القائم. يضيف ترحيل تحسينات سير العمل تفاصيل المواد، والتحقق الصارم من الاسم والهاتف، وسحب البائع لطلبه المعلّق، والإلغاء الآمن للطلب الجاهز مع إعادة المخزون، وتقييم المخزون من التكاليف المسجلة فقط. يضيف ترحيل الطلبات دون اتصال مفتاحاً فريداً لكل طلب كي لا يؤدي تكرار المحاولة إلى تكرار الطلب على الخادم. يتطلب الإلغاء التلقائي تفعيل إضافة `pg_cron` في Supabase؛ يثبّت الترحيل الإضافة وجدولة الفحص كل خمس دقائق، ويُلغى الطلب بعد تجاوزه 24 ساعة من التجهيز.
2. أنشئ حساب المالك الأول من **Supabase Dashboard → Authentication → Users → Add user**. استخدم بريداً اصطناعياً باسم `اسم-المستخدم@users.sinna.invalid` وكلمة مرور المالك، وفعّل تأكيد البريد للحساب.
3. انسخ UUID لحساب المالك، ثم عيّن اسم المستخدم والاسم والدور في SQL Editor:

   ```sql
   update public.profiles
   set username = 'ownername',
       full_name = 'اسم المالك',
       role = 1
   where id = 'AUTH-USER-UUID';
   ```

4. طبّق مخطط قاعدة البيانات قبل النشر، وإلا سيعرض الموقع قائمة مواد فارغة ولن تُقبل الطلبات.
5. في إعدادات Netlify → Environment variables، أضف:
   - `SUPABASE_URL` = رابط المشروع.
   - `SUPABASE_PUBLISHABLE_KEY` = مفتاح النشر العام للمشروع.
   - `SUPABASE_SECRET_KEY` = المفتاح السري، للدالة الخادمية فقط. **لا تضعه في HTML أو JavaScript أو Git.**
6. افتح الموقع وسجّل الدخول باسم المستخدم وكلمة المرور اللذين أنشأتهما في Supabase Auth. بعد الدخول، أضف المواد من صفحة «المخزون» وأنشئ حسابات البائعين من صفحة «حسابات البائعين»؛ سيُنشأ حساب البائع بدور `2` تلقائياً.

تكلفة شراء الوحدة اختيارية عند تعبئة المخزون. لا تُحتسب قيمة المخزون أو تكلفة البضاعة أو الربح للوحدات التي لا تملك تكلفة شراء مسجلة؛ يعرض تقرير المالك قيمة الوحدات المعروفة منفصلة عن المبيعات ويبيّن عدد الوحدات مجهولة التكلفة. بعد ترحيل الحسابات، يمكن إدخال تكلفة المخزون القديم من صفحة «الأرباح والمصروفات». تُحسب أسعار البيع من هامش الربح كنسبة من سعر البيع، وتبدأ النسبة العامة عند 10% ويمكن تخصيصها لكل مادة. تشمل تقارير الصفحة المبيعات المباشرة والطلبات المستلمة والمصروفات التشغيلية المسجلة ضمن الفترة المختارة.

يمكن للبائع إرسال طلب تزويد لمادة قاربت على النفاد أو ترشيح مادة يتوقع زيادة الطلب عليها، مع تحديد الكمية وملاحظة اختيارية. يراجع المالك جميع الطلبات والترشيحات ويقبلها أو يرفضها مع رد اختياري، ويمكن للبائع سحب طلبه المعلّق مع إبقاء أثره في السجل. قبول الطلب لا يغيّر رصيد المخزون؛ عند وصول البضاعة، يسجل المالك التعبئة من صفحة المخزون.

يستخدم الموقع إعدادات المشروع العامة في واجهته للاتصال بمواد Supabase وطلباتها. تُنفّذ عمليات المرتجع والتعديل والأرشفة والتعبئة عبر دوال قاعدة البيانات التي تتحقق من الدور والملكية والكميات؛ سجل البائع مقيد بعملياته الخاصة، بينما يراجع المالك السجلات النشطة والمؤرشفة. لا تعرض واجهة الطالب أعداد المخزون. الدالة في [`netlify/functions/auth.mjs`](./netlify/functions/auth.mjs) تتحقق من دور الحساب وتنفذ تحديث حسابات البائعين بصلاحية الخادم. لا تنشر الموقع بالسحب والإفلات لمجلد HTML فقط؛ يجب نشر Netlify Function أيضاً.

## حدود النسخة الحالية

يجب تشغيل مخطط قاعدة البيانات وترحيل إدارة المبيعات وإعداد متغيرات Netlify قبل تفعيل الميزات الجديدة. تعرض الواجهة آخر 1000 معاملة محمّلة؛ عمليات التحقق من مهلة 24 ساعة والصلاحيات والمخزون تتم خادمياً في قاعدة البيانات.

**أمان:** المفتاح السري الذي أُرسل في المحادثة ينبغي تدويره/إلغاؤه من Supabase وإصدار مفتاح جديد، ثم حفظ الجديد فقط في إعدادات Netlify. مفتاح النشر العام وحده موضوع في الواجهة، وهو مصمم ليكون عاماً.
